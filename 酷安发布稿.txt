双击电源键开手电筒：ColorOS 端的 LSPosed 重构方案


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━


【前言】

本次发布的是一个完全重构版本，不是对上一版 Magisk 模块的修补。

旧方案通过 Magisk 的 getevent 旁听电源键事件，只能“看到”按键，无法干预系统行为，由此产生了一系列无法绕开的副作用。

新方案改用 LSPosed 注入 system_server，在系统手势判定完成之前接管事件，从根上解决这些问题。

Magisk 侧的监听方案已完全移除。


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━


【技术实现】

ColorOS 并未使用 AOSP 的 GestureLauncherService 来处理电源键。日志验证如下：

　　[PWM] POWER action=0
　　（GestureLauncherService 全程无输出）
　　（PowerKeyRule#onMultiPress 无输出）

按键确实进入了 system_server，但 AOSP 那条链路全程沉默。

ColorOS 使用自己的实现，落在：

　　PhoneWindowManager.interceptPowerKeyDown(KeyEvent, boolean, boolean)
　　PhoneWindowManager.interceptPowerKeyUp(KeyEvent, boolean)

模块直接 hook 这两个方法，在系统完成手势判定前接管事件。

这也解释了为什么市面上多数通用模块（如 Pixel Suite）在这类机型上无效——它们 hook 的是 AOSP 那条链路，而 ColorOS 根本不走。


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━


【解决了旧模块的三个问题】

一、自动亮度被强制拉满

旧方案在开灯时会切换屏幕亮度模式，暗环境下屏幕刺眼，而手电筒恰恰多数在暗环境使用。

新方案不触碰任何亮度相关设置，开灯只影响闪光灯本身。


二、亮屏双击必定息屏

旧方案只能旁观，系统照常执行灭屏，需要重新解锁才能回到桌面。

新方案在抬起事件中消费手势，屏幕保持点亮，当前操作不受影响。


三、快速连续双击会被吞

旧方案存在防抖死区，连续开关时部分按键丢失，表现为“按了没反应”。

新方案每次手势独立判定，不设冷却。


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━


【当前效果】

双击电源键：开 / 关手电筒
亮屏双击：屏幕不变，不影响当前操作
连续双击：不吞键
单击电源键：完全交给系统，零延迟
长按电源键：完全交给系统，电源菜单正常


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━


【使用前提｜必须开启】

卡包 App → 我的 → 设置 → 双击电源键唤起快捷服务

该选项关闭时，系统不会启用双击判定：两次按压会被当作两次独立的单击立即执行，模块拿不到判定窗口，功能不生效。

开启之后，双击电源键不再弹出卡包，改由模块接管。

因此：卡包的双击唤起功能会失效，按需下载使用。


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━


【适配】

机型：一加 13（PJZ110）
系统：ColorOS 16 / Android 17

其它机型未验证。

判断依据：LSPosed 日志中出现 [PWM] DOWN 说明 hook 点对得上；若只出现 [PWM] POWER 而没有 DOWN，说明该 ROM 使用了另一套实现，需要调整 hook 点。


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━


【安装】

一、设备已 root，并安装 LSPosed（Zygisk 版本）
二、安装 APK
三、打开 LSPosed → 模块 → 启用 DoubleTapTorch
四、作用域仅勾选「系统框架」（android），其它一律不勾
五、重启手机

第四步最容易遗漏。作用域勾错或不勾，模块完全不工作，表现为“装了没反应”。


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━


【已知限制】

一、亮度低于旧的 Magisk 模块

旧 Magisk 模块直接写 sysfs 节点，取值为 500（节点上限）。

新方案走 CameraManager 的强度档位，最高档对应 sysfs 值 50。

相机 API 在该机型上只暴露 4 个强度档位，最高档对应节点值 50，而节点上限为 500。若要达到 500，需要 root 直接写 /sys/class/leds/led:torch_0/brightness，需要额外的守护进程配合，本版本未内置。


二、息屏双击时，屏幕会短暂点亮

息屏状态下双击开灯，第一次按下会先把屏幕点亮一下。

原因：本方案不拦截“按下”事件，只处理“抬起”。若要在按下时就吞掉事件，单击电源键就必须延迟执行，代价是每次单击都有可感知的延迟。两个效果无法同时满足，本版本选择了单击零延迟。


三、双击判定窗口 501ms

两次按压间隔需在 501ms 以内才会被判定为双击。间隔过长会被系统当作两次独立单击，表现为“屏幕灭了又亮”。

该值依据实测按键间隔分布（148~568ms）确定，覆盖绝大部分操作节奏。

【回退方法】

卸载模块并重启，双击电源键即可恢复卡包功能。

另外注意：如果此前使用过 Magisk 版本，需确认 /data/adb/modules/Power_double_torch/ 下存在 disable 标记文件，避免两套逻辑同时生效导致“开灯后立即被关闭”。


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━


【结语】

这个模块解决的是 ColorOS 一个很具体的取舍：系统把双击电源键绑定给卡包，且设置中不提供其它选项。

遇到问题请在 GitHub 提 Issue，附上机型、ROM 版本，以及 LSPosed 日志中是否出现 [PWM] DOWN。
